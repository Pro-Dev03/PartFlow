# تقرير إصلاح وتجهيز إصدار Windows

**التاريخ:** 2026-09-13  
**المشروع:** PartFlow  
**الفرع:** `main`

## الملخص

تم تنفيذ مجموعة إصلاحات وتحسينات على تطبيق PartFlow، ثم تجهيز نسخة Windows موقعة وقابلة للتثبيت. شملت الأعمال تحسين شاشة نقطة البيع، إصلاح إدارة المنتجات والأسعار، معالجة مشكلة دمج المنتجات في السلة، وتحويل تخزين صور المنتجات إلى تخزين دائم مناسب للنسخة التنفيذية.

## الإصلاحات الوظيفية

### نقطة البيع والسلة

- جعل تخطيط Sidebar نقطة البيع يعتمد على صفوف Grid واضحة:
  - العميل.
  - إعدادات الفاتورة.
  - السلة المرنة.
  - الدفع.
- جعل السلة تستغل المساحة المتاحة قبل بطاقة الدفع.
- حصر التمرير داخل قائمة منتجات السلة فقط.
- إبقاء بطاقة الدفع وزر **إتمام البيع** ظاهرين دون تداخل.
- تقليل المساحات غير الضرورية في مناطق العميل والفاتورة والدفع.
- إصلاح دمج منتجات مختلفة في السلة عندما لا يكون لها باركود.
- أصبح مفتاح المنتج في السلة يستخدم بالترتيب:

```text
barcode -> inventoryItemId -> SKU -> product ID
```

وبذلك يظهر الكابل والكيبورد كسطرين مستقلين حتى عند عدم وجود باركود.

### SKU

- إضافة توليد تلقائي عشوائي لرمز المنتج بصيغة:

```text
SKU-XXXXXXXXXX
```

- يظهر الرمز تلقائيًا عند إنشاء منتج جديد.
- يمكن تعديله يدويًا قبل الحفظ.
- توحيد التوليد في المخزون، نقطة البيع، ونموذج المنتج العام.

### الأسعار

- إصلاح إعادة حساب سعر البيع عند تغيير سعر التكلفة.
- منع بقاء قيمة قديمة مثل `1.11` بعد تغيير التكلفة إلى `100`.
- أصبح السعر المقترح يحسب حسب هامش الربح المضبوط.
- جعل السعر المقترح وسعر البيع أرقامًا صحيحة دون كسور.
- إبقاء سعر التكلفة قابلًا لإدخال الكسور عند الحاجة.

مثال: تكلفة `100₪` وهامش `10%` تنتج سعر بيع مقترح `111₪`.

### تسميات المخزون

تم استبدال النص المضلل **الكمية بدون فاتورة** بـ:

- **الكمية الافتتاحية** عند إضافة منتج.
- **الكمية الحالية** عند تعديل منتج.

مع إضافة توضيح أن الكمية الافتتاحية تضاف مباشرة إلى المخزون دون إنشاء فاتورة شراء.

## تخزين صور المنتجات

### قبل الإصلاح

كانت الصور تحفظ كـ Base64 داخل `localStorage` تحت المفتاح:

```text
partflow.local.product-images
```

وهذا غير مناسب للإنتاج بسبب حد حجم التخزين وارتباطه ببيانات المتصفح.

### بعد الإصلاح

في نسخة Electron، تحفظ الصور داخل مجلد بيانات المستخدم:

```text
%APPDATA%\PartFlow\data\product-images\
```

وقاعدة البيانات المحلية تحفظ في:

```text
%APPDATA%\PartFlow\data\partflow.db
```

تمت إضافة قناة IPC آمنة بين الواجهة وElectron من أجل:

- قراءة الصور.
- حفظ الصور.
- حذف الصور.
- استبدال الصور بأمان باستخدام ملف مؤقت.

كما تمت إضافة ترقية تلقائية للصور القديمة من `localStorage` إلى التخزين الجديد عند بدء التطبيق.

### حماية البيانات عند التحديث

إعداد Installer يحتوي على:

```json
"deleteAppDataOnUninstall": false
```

لذلك تبقى قاعدة البيانات والصور خارج مجلد تثبيت البرنامج عند التحديث أو إعادة تثبيت النسخة فوق النسخة الحالية.

## التحقق والاختبارات

تم تنفيذ الاختبارات التالية بنجاح:

```powershell
go test ./...
npm run build:check
npm run lint:types
node --check electron/main.js
node --check electron/preload.js
```

كما تم التحقق بصريًا من شاشة نقطة البيع وقياسات السلة والدفع.

## بناء Windows

تم تشغيل سكربت الإصدار:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-win-final-installer.ps1 -Version 1.0.0
```

تم إصلاح سكربت البناء ليقوم بـ:

- استخدام مجلد Electron الصحيح `dist-electron-internal`.
- إيقاف العملية عند غياب مخرجات Electron.
- تنظيف حزمة runtime قبل النسخ.
- منع بقاء ملفات قديمة مثل `electron.exe` داخل الحزمة النهائية.

## التوقيع والشهادة

تم توقيع الملفات بنجاح باستخدام:

```text
CN=PartFlow Internal Code Signing
```

وحالة التوقيع كانت:

```text
Valid
```

وتم التحقق من توقيع:

- Installer.
- Portable executable.
- `PartFlow.exe` داخل `win-unpacked`.

## الأيقونات

تم توليد أيقونة Windows متعددة الأحجام من خلال:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\generate-partflow-icon.ps1
```

الأحجام المضمنة:

```text
16, 24, 32, 48, 64, 128, 256
```

ملف الأيقونة:

```text
frontend/public/partflow-logo.ico
```

وتم التحقق من وجوده داخل موارد التطبيق المجمعة.
