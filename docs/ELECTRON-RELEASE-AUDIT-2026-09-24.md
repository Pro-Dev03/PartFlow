# تقرير تدقيق النظام وتجهيز إصدار Electron

**التاريخ:** 2026-09-24  
**النظام:** PartFlow  
**المنصة المستهدفة:** Windows x64 / Electron

## الحالة

اكتمل أحدث بناء نظيف لحزمة Windows x64 للإصدار `1.0.0` في 2026-09-24، وأُنشئت الحزمة في [dist/windows-release/partflow-bundle](../dist/windows-release/partflow-bundle). نجحت `npm ci` و`npm audit` (صفر ثغرات) و27 ملف اختبار تضم 123 اختبارًا وفحص TypeScript وبناء Vite/PWA. أنشأ Electron Builder المثبّت والنسخة المحمولة والتطبيق المفكوك والخادم المحلي. أضيف فحص لعروض النوافذ داخل CSS المحفوظ في ASAR، واجتازته الحزمة.

في هذه الإعادة، كشف فاحص ASAR أن استخراج CSS يحتاج الاحتفاظ بفواصل المسار الخاصة بويندوز. صُحّح الفاحص وأعيد البناء بنجاح. أكد وجود ملفات Electron والخط والشعار ومجلدات الموارد وعقود مسارات قاعدة البيانات والصور والسجلات ومفتاح الأوفلاين والخادم المحلي، كما أكد قواعد العروض داخل CSS. تطابقت الأحجام وبصمات SHA-256 للملفات التسعة في `release-manifest.json` مع الملفات المنشورة.

تحقق سكربت الإصدار من صلاحية توقيع المثبّت والنسخة المحمولة وملف التطبيق والـBackend أثناء البناء. تستخدم الحزمة شهادة PartFlow داخلية ذاتية الاعتماد. لذلك لا تعادل هوية ناشر موثوقة من جهة شهادات عامة، وقد يظهر تحذير ناشر أو SmartScreen على جهاز المتجر قبل تثبيت الشهادة. ما زال يلزم اختبار التثبيت والتشغيل على جهاز Windows نظيف، وللتوزيع التجاري الأوسع يوصى بشهادة توقيع تطبيقات من جهة عامة.

يسجل البيان وقت البناء `2026-09-24T11:00:23Z` والالتزام الأساسي `c22ec6d` مع `workingTreeDirty: true`؛ أي إن ملفات المصدر المبنية تضمنت تعديلات محلية لم تكن ملتزمة في ذلك الالتزام. بصمات البيان تخص الملفات التنفيذية المدرجة ولا تشمل ملف manifest نفسه. أبقى سكربت الإصدار الحزمتين السابقتين في مجلدات احتياطية بجانب الحزمة الجديدة.

## الإخفاقات التي عولجت

- ترفض شاشة المصروفات الآن تواريخ الإدخال غير المكتملة أو غير الصالحة بدل تفسيرها كتاريخ مختلف.
- أضيف اسم عمود صريح لاستعلام فاتورة الشراء بما يتوافق مع ربط نتائج `sqlx` بالحقول.
- حُدّث اختبار لوحة الدفع ليتحقق من نافذة تقسيم الدفع وتأكيد ملخصها.
- صُحّح تجهيز كمية المخزون في اختبار حذف عنصر مباع؛ السلوك القائم لا ينقص المتاح عند حذف عنصر حالته `SOLD`.
- عُزل تشغيل Electron: لا يقتل التطبيق عملية أخرى عشوائية تستخدم المنفذ 8080، ويمنع تشغيل نسختين، ويتوقف برسالة واضحة إذا تعذر تشغيل Backend الخاص بالتطبيق.
- عولجت ثغرات الاعتماديات التي ظهرت في الفحص السابق، وأصبح آخر فحص ناجح لـ`npm audit` بلا ثغرات.
- عولج انضغاط محتوى النوافذ: كان Tailwind يترجم فئات مثل `max-w-2xl` إلى قيمة المسافة المخصصة `32px`، بسبب تداخل أسماء قياسات العرض مع رموز المسافات في إعدادات التصميم. جرى فحص مكونات النوافذ والحوار ومواضع استخدامها، واستبدال هذه الفئات بقيم عرض صريحة في 19 ملفًا، بما فيها نافذة إنشاء الشراء. تحقّق فاحص الإصدار من قواعد CSS الناتجة داخل ASAR لمنع رجوع هذا الخلل.

## ملفات الإصدار

- `PartFlow-1.0.0-setup.exe` — المثبّت.
- `PartFlow-1.0.0-portable.exe` — نسخة محمولة.
- `partflow-api.exe` — Backend مستقل للتشخيص.
- `win-unpacked/` — التطبيق وموارده والـBackend المضمّن.
- `release-manifest.json` — الالتزام الأساسي، حالة شجرة المصدر، وأحجام وبصمات SHA-256.

أُضيف [build-win-final-installer.ps1](../scripts/build-win-final-installer.ps1) لبناء مرحلي نظيف، وتشغيل الاختبارات والبناء، وإنشاء المثبّت والنسخة المحمولة بتوقيع مفروض، والتحقق من التوقيعات، ثم إنشاء الحزمة وmanifest. يرفض السكربت متابعة البناء إذا لم يجد المفتاح الخاص المطابق والشهادة موثوقة في مخزن Windows للمستخدم الذي يبني الإصدار. لا يُضمّن المفتاح الخاص في التطبيق.

ثبت Electron الآن جذر بيانات المستخدم صراحةً إلى `%APPDATA%\PartFlow` في Windows، ليبقى مستقراً حتى لو تغير مسار تثبيت البرنامج أو اسمه في إعداد الحزمة. المسارات التشغيلية هي:

| البيانات | المسار |
|---|---|
| قاعدة SQLite | `%APPDATA%\PartFlow\data\partflow.db` |
| صور المنتجات | `%APPDATA%\PartFlow\data\product-images\` |
| صور التصنيفات | `%APPDATA%\PartFlow\data\category-images\` |
| صور أنواع القطع | `%APPDATA%\PartFlow\data\part-type-images\` |
| سجل Backend | `%APPDATA%\PartFlow\logs\backend.log` |
| مفتاح منح الأوفلاين العام | `%APPDATA%\PartFlow\offline-grant-public-key.txt` |

مسار قاعدة البيانات نفسه يُمرر إلى Backend عبر `PARTFLOW_LOCAL_DB_PATH`. ملفات التشغيل الثابتة تبقى داخل `resources`، والخط العربي `NotoNaskhArabic.ttf` داخل `app.asar/dist/fonts`. يفحص سكربت الإصدار وجود هذه الملفات وعقود المسارات داخل الحزمة قبل نسخها إلى مجلد الإصدار. لا تُضمّن قاعدة متجر في الحزمة، وتبقى بيانات المستخدم خارج مجلد البرنامج ولا تُحذف عند إلغاء التثبيت (`deleteAppDataOnUninstall: false`).

يستورد المثبّت الشهادة العامة الداخلية إلى مخازن الثقة للمستخدم الحالي، وهذا الترتيب لا يزيل تحذير الثقة الأولي عند تشغيل المثبّت على جهاز جديد.

## بنية الاتصال الموصى بها لهذا الإصدار

إعداد Electron الافتراضي يشغّل العمليات التشغيلية عبر الـBackend المحلي وقاعدة SQLite على جهاز المتجر. يستخدم النظام API السحابي للمصادقة والاشتراك والمزامنة. هذا مناسب لمتجر يعمل على جهاز واحد ويحتاج استمرار البيع عند انقطاع الإنترنت، مع بقاء التحقق من الاشتراك خاضعًا لسياسة المنحة الموقعة ومهلة الأوفلاين.

فحص `/health` يثبت أن API يستجيب وقت الفحص فقط؛ لا يثبت جاهزية خطة الاستضافة للإنتاج أو وجود نسخ احتياطية أو اتفاقية توفر. إذا كانت خدمة Render على الخطة المجانية، فتوثيق Render يذكر أنها قد تدخل السكون بعد 15 دقيقة خمولًا، ويستغرق إيقاظها نحو دقيقة، كما أن نظام الملفات المحلي فيها مؤقت. يلزم تشغيل مدفوع وقاعدة بيانات دائمة ونسخ احتياطية مجرّبة قبل جعلها مخزن العمليات الوحيد. راجع [قيود الخدمات المجانية](https://render.com/docs/free)، [الأقراص الدائمة](https://render.com/docs/disks)، و[نسخ Render Postgres الاحتياطية](https://render.com/docs/postgresql-backups).

لتشغيل المتجر دون إنترنت، يجب إعداد المفتاح العام لمنحة الأوفلاين على جهاز المستخدم كما هو موضح في [استراتيجية الاشتراك دون اتصال](SUBSCRIPTION-OFFLINE-STRATEGY.md). لا يوضع المفتاح الخاص لمنحة الأوفلاين في التطبيق.

## إغلاق التدقيق والإصدار النهائي

اكتملت معالجة النتائج العملية ذات الأولوية في التدقيق، وشمل ذلك سلامة معاملات البيع والمشتريات والمرتجعات، منع بيع مخزون سالب عند التزامن، تسوية دفعات العملاء والتجار داخل معاملات ذرية، حفظ قيود الديون والتحصيلات، الأرشفة الآمنة للعملاء وتصنيفات المصروفات بدل حذف التاريخ المالي، وتصحيح حساب المحصل اليومي ومنع احتساب دفعة البيع مرتين.

عولجت كذلك جلسات المصادقة حتى لا يؤدي تسجيل الخروج اليدوي أو انقطاع الشبكة المؤقت إلى طلبات تحديث متأخرة أو مسح جلسة غير مبرر. تستمر صلاحية الأوفلاين بالمنحة الموقعة لمدة أقصاها 72 ساعة من آخر تحقق ناجح أو حتى انتهاء الاشتراك، أيهما أسبق.

أضيفت جداول ديون العملاء والتجار والتحصيلات إلى مخططي PostgreSQL وSQLite، وثُبتت مسارات قاعدة البيانات والصور والسجلات ومفتاح الأوفلاين في `%APPDATA%\PartFlow`. كما أصبح تصدير سجل التدقيق CSV آمنًا وقابلًا للتنزيل من الإعدادات، وأزيلت عناصر إعدادات التدقيق التي لم تكن تنفذ أي عملية فعلية.
